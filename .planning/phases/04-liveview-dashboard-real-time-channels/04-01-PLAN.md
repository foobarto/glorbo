<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| inotify → Watcher → PubSub → LiveView | Filesystem events cross into Elixir runtime; path strings are inputs from kernel (not user) but agent processes (which are adversarial in v1 trust model) can create paths. |
| Director (browser) → LiveSocket → `GlorboWeb.Actions` → `File.write!/3` | Director-authored strings (channel body, wake reason) cross into Elixir then land on disk; agents subsequently read them. |
| `~/.glorbo/config.md` → `Glorbo.Config` → `config/runtime.exs` | Config file is Director-owned (chmod 0600); parser must not crash on malformed input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `channels/<ch>.md` via Actions.post_message | mitigate | Validate `channel` matches `~r/\A[a-z0-9-]+\z/`; `File.lstat!/1` regular-file check before append (symlink attack defense); reject body > 10 KiB. |
| T-04-02 | Tampering | `state/wake-request.md` written by Director but agent could attempt to write it too | mitigate | Actions.wake_agent writes `state/` files; Phase 3 bwrap argv excludes `state/` from agent mounts (verified in Phase 3 tests — defense in depth). Watcher emits `agents:<slug>:wake` topic only — not an agent wake-trigger alone; Agent.Server validates the file was written by Elixir (stat UID = host UID). |
| T-04-03 | Tampering | `TaskDefinition.write/2` corrupts task file on partial write | mitigate | Atomic tmp + `File.rename!/2` on same filesystem; unsupported keys rejected before open. On write error, remove tmp and return `{:error, _}`. Narrow key allowlist (`status`, `denial_reason`) — never rewrite arbitrary frontmatter. |
| T-04-04 | DoS | `StdoutStreamer` reads runaway agent stdout | mitigate | 64KB read chunk per poll + 300ms poll interval + downstream LV `stream/4` `limit: -1000` bound memory at both ends. |
| T-04-05 | Information disclosure | `Glorbo.Config.load/1` leaks `dashboard_token:` in error messages / logs | mitigate | Never include config values in raised errors or Logger.error; return opaque `{:error, :config_parse}` tuples. |
| T-04-06 | Spoofing | CSRF on LiveView post_message | mitigate | Phoenix LiveView default CSRF token passed through `LiveSocket` params; wired in `root.html.heex` via `meta name="csrf-token"` (already present in root.html.heex). |
| T-04-07 | Elevation of privilege | PubSub topic typo delivers wrong-company events | mitigate | Build topics via a single helper (see Task 2); tests assert mismatched events dropped. Company isolation preserved from Phase 3. |
| T-04-08 | Tampering | Path traversal via `channel` / `agent` param (`../../etc/passwd`) | mitigate | Actions validates with `~r/\A[a-z0-9-]+\z/`; fails fast with `{:error, :invalid_slug}`. |
</threat_model>

    ```elixir
    defmodule Glorbo.Config do
      @moduledoc """
      Parser for `~/.glorbo/config.md` — read-once at boot, written on first
      boot if missing. Supplies `secret_key_base`, `dashboard_token` (opt),
      `host`, `port` to `config/runtime.exs`.

      File shape (YAML frontmatter with a pass-through markdown body):

          ---
          secret_key_base: <base64, 64+ bytes>
          dashboard_token: null            # optional bearer for LAN exposure (D-06)
          host: "127.0.0.1"                # D-06 loopback default
          port: 4000
          ---

          # Glorbo configuration
          (human-editable notes here; Glorbo only reads the frontmatter)

      Errors never leak config values (T-04-05).
      """

      alias Glorbo.Filesystem.Frontmatter

      @type config :: %{
              secret_key_base: String.t(),
              dashboard_token: String.t() | nil,
              host: String.t(),
              port: pos_integer()
            }

      @spec load(Path.t()) :: {:ok, config()} | {:error, :config_parse}
      def load(base \\ Path.expand("~/.glorbo")) do
        path = Path.join(base, "config.md")
        unless File.exists?(path), do: write_default!(path)

        with {:ok, content} <- File.read(path),
             {:ok, meta, _body} <- Frontmatter.parse(content) do
          {:ok,
           %{
             secret_key_base: to_string(meta["secret_key_base"] || generate_secret()),
             dashboard_token: maybe_string(meta["dashboard_token"]),
             host: to_string(meta["host"] || "127.0.0.1"),
             port: to_int(meta["port"] || 4000)
           }}
        else
          _ -> {:error, :config_parse}
        end
      end

      defp write_default!(path) do
        File.mkdir_p!(Path.dirname(path))
        secret = generate_secret()

        body = """
        ---
        secret_key_base: #{secret}
        dashboard_token: null
        host: "127.0.0.1"
        port: 4000
        ---

        # Glorbo configuration

        Generated by Glorbo on first boot. Edit `host:` to `0.0.0.0` to accept
        LAN connections, and set `dashboard_token:` to require `?token=<...>`
        on the URL.
        """

        File.write!(path, body, [:sync])
        File.chmod!(path, 0o600)
      end

      defp generate_secret, do: :crypto.strong_rand_bytes(64) |> Base.encode64()

      defp maybe_string(nil), do: nil
      defp maybe_string(""), do: nil
      defp maybe_string(s) when is_binary(s), do: s
      defp maybe_string(other), do: to_string(other)

      defp to_int(n) when is_integer(n), do: n
      defp to_int(s) when is_binary(s), do: String.to_integer(s)
    end
    ```
