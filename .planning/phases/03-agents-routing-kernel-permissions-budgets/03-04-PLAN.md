<objective>
Implement Phase 3's approval gate — the mechanism that pauses execution of tasks with `requires_approval: director` in their frontmatter (SEC-04) and defends the agent-creation trust boundary by requiring Director-driven file-edit approval flow. This plan is the smallest Wave-1 plan (two modules, two test files); it is the most self-contained because approval is a quiet, narrow feature: write sentinel, watch for status-flip, resolve.

This plan includes the `TaskDefinition` parser because it's intrinsic to approval-gate logic: Gate needs `requires_approval?/1` + `status/1` extraction from task files, and no other plan in Phase 3 needs task parsing (Agent.Server in Plan 03-03 only needs the task's *prompt body*, delivered via the task_map passed in `wake/3` — Plan 03-05's inbox scanner is the one that actually loads task files, and it will use TaskDefinition).

Purpose: Keep approval logic testable without the supervision tree (tests drive PubSub directly); keep it robust to Gate crashes (state rebuilds from filesystem + SQLite per D-45); keep it additive to AUDIT_EVENTS.md (two new event keys registered at plan boundary).

Output: 2 modules + 2 test files + AUDIT_EVENTS.md extension with two new keys (`approval.spurious`, `approval.parse_error`, `approval.rename_failed`).
</objective>

defmodule Glorbo.TaskDefinition do
  @type approval_mode :: :director | nil

  @type t :: %__MODULE__{
          task_path: String.t(),               # "projects/foo/tasks/t-01.md" — relative to company dir
          task_id: String.t(),                  # "t-01"
          title: String.t() | nil,
          status: String.t() | nil,             # "pending" | "in-progress" | "pending-approval" | "approved" | "denied" | "completed"
          assigned_to: String.t() | nil,        # agent slug, if scoped
          requires_approval: approval_mode(),
          denial_reason: String.t() | nil,
          prompt_body: String.t(),              # markdown body (frontmatter stripped)
          file_path: String.t()                 # absolute path
        }
  defstruct [:task_path, :task_id, :title, :status, :assigned_to, :requires_approval,
             :denial_reason, :prompt_body, :file_path]

  @spec parse_file(String.t(), keyword()) :: {:ok, t()} | {:error, term()}
  # opts: :base (default ~/.glorbo), :company (required — used to compute task_path from file_path)

  @spec parse_frontmatter(map(), keyword()) :: {:ok, partial_t :: map()} | {:error, term()}
  # Pure — no IO.

  @spec requires_approval?(t()) :: boolean()
end

# Awaiting Director approval

**Task:** Delete production database backups older than 90 days

This task requires approval because `requires_approval: director` is set in its frontmatter.
To approve: edit the task file and set `status: approved` in its frontmatter.
To deny: edit the task file and set `status: denied` in its frontmatter.
