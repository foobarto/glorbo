# E2E Wake-Path Validation — 2026-04-18

Live verification of the three wake-path scenarios against real
bwrap + claude-code, against the running dev server (`mix phx.server`)
on `localhost:4000`. Browser automation via agent-browser attached
to Chrome CDP on port 9222 (Bazzite workaround per memory note).

## Scope

Three scenarios from task #120:

1. Manual Wake button → dispatch → reply
2. Inbox-routed task → agent pickup → response
3. Chat @mention / DM → wake → response

## Results

### ✓ Scenario 1 — Manual Wake button

**Works.** `director wake` → `agent.dispatch` → `agent.complete` in
9624ms, exit 0. Reply file landed at
`{workspace}/.glorbo/outbox/<ts>-<id>.md`.

Audit trail:

```
agent.wake_request  actor=director      target=agents/ceo
agent.dispatch      actor=system        task_path=null
agent.complete      actor=ceo           exit_status=0 duration_ms=9624
```

### ✓ Scenario 2 (partial) — Inbox message triggers wake

**Wake fires.** inotify sees the inbox write; `default_inbox_scan/2`
picks up the file; dispatch runs; agent replies with correct
content ("ACKNOWLEDGED at 2026-04-18T11:20:00Z").

But **three downstream gaps** surfaced (see Findings):

- F1: inbox file never drained — causes redispatch loop (#123)
- F2: reply lands in workspace outbox, not Router-watched outbox (#124)
- F3: Router never sees the reply, so no reply routing happens

### ⚠ Scenario 3 — @mention chat post

**Wake fires** with `trigger: :mention` and the mention file lands
at `inbox/mentions/<ts>-<channel>.md`. But the wake dispatches the
OLDEST inbox file (the leftover scenario-2 file), not the mention.
Agent responds to the unrelated stale message.

Fix is #125 — thread trigger through to `default_inbox_scan/2` so
mention wakes prefer mentions/ dir.

## Findings summary

| # | Issue | Severity | Task |
|---|-------|----------|------|
| F1 | Inbox files never drained; redispatch loop | **CRITICAL** — observed 6× redispatch of same file in 30s | #123 |
| F2 | Reply file written to workspace outbox not Router outbox | High — breaks chat/DM reply routing end-to-end | #124 |
| F3 | Mention wake picks oldest inbox instead of mention file | High — agent ignores the thing that woke it | #125 |
| F4 | No path from kanban assignment → agent dispatch | Medium — design gap, not a bug per se | #126 |

## Budget impact

Six redundant dispatches against claude-code at ~9-16s each ≈ 60s
of Sonnet 4.5 usage burned while the loop ran. Small but
alarming — a stuck inbox file at production scale would drain
budget invisibly. F1 is the highest priority.

## What works

- Wake PubSub topic (GEP-16 §1): Director wake → PubSub → AgentServer ✓
- bwrap sandbox boundary (GEP-5): filesystem view correct, auth binds mount ✓
- Dispatcher reply-file contract (GEP-8 D1 + stdout fallback GEP-16 §7): CEO replies captured ✓
- Budget tracking: `agent.complete` records duration_ms ✓
- @mention detection: chat.post → agent.wake with trigger:mention ✓

## What's broken

- Post-dispatch cleanup (F1) — the most load-bearing of the four; everything else downstream depends on inbox state transitioning forward
- Reply routing (F2) — the wake path works one-way (director → agent) but two-way conversation is broken until this lands
- Trigger-aware scanning (F3) — trigger carries enough info to pick the right file; `default_inbox_scan/2` just ignores it

## Not in scope

- #126 kanban → agent is a design question, not a bug. Current system
  relies on inbox as the sole wake carrier. Deferred to task discussion.
