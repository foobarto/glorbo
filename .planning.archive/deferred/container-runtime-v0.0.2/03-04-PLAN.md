<objective>
Implement the approval-gate system that pauses tasks with `requires_approval: director` until the Director flips the task file's frontmatter `status:` to `approved` (D-30..D-33). This plan is the smallest of Wave 1 — only 2 modules (TaskDefinition parser + Gate GenServer) and 2 test files. It includes the AGT-05 defense-in-depth layer at task parse time (the Router-side AGT-05 enforcement lives in Plan 02; this plan adds parse-time hardening so that even if Router classification slipped, an inline-agent-definition smuggled inside a task file would be rejected).

This plan does NOT subscribe to Watcher events directly — it exposes `handle_task_status_change/3` which Plan 05 wires into Watcher's path-prefix routing (`projects/*/tasks/*.md` change → diff frontmatter → if status changed, call Gate). Plan 03's Dispatch checks `requires_approval` and calls Gate.request_approval instead of WorkerClient when approval is needed.

Files modified are DISJOINT from Plans 02 + 03 + 05 — same wave, no overlap. Tests are pure-Elixir + DataCase, no inotify, no podman, no container.

Output: 2 modules + 2 test files. The Gate is fully testable via direct API calls; Plan 05's integration test exercises the end-to-end Watcher → Gate → Agent.Server.wake flow.
</objective>
